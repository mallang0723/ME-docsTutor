# Marinara Docs Tutor 로어북 확장

*[English guide here](./README.en.md)*

Marinara Engine에 들어 있는 **공식 문서(docs)를 읽어 초보자용 지식 로어북을
자동 생성**하고, 선택한 캐릭터에 장착해 주는 확장입니다.

장착된 캐릭터는 채팅 중에 마리나라 기능에 대한 질문("로어북이 뭐야?",
"프리셋은 어떻게 써?")에 문서 기반으로 답할 수 있게 됩니다.

- 문서 원본은 **수정하지 않습니다**
- 재실행하면 로어북 **항목만 갱신**됩니다 (중복 생성 없음)
- 이 확장이 만들지 않은 로어북은 **절대 건드리지 않습니다**

## 대응 버전

| 항목 | 내용 |
|---|---|
| 이 확장 | v1.3.0 |
| 검증한 호스트 | **Marinara Engine 2.5.0** |
| 검증한 문서 | 같은 Marinara 2.5.0에 들어 있는 공식 문서 (`docs/`, 영어 원문) |
| 설치 가능 범위 | 매니페스트에 최소 버전 제한은 없습니다. 2.4.x는 같은 확장 시스템이지만 미검증, 2.3.4 이하 정식 버전은 확장 시스템이 달라 동작하지 않습니다 |
| 검증 날짜 | 2026-10-20 |

- **Marinara Engine 2.5.0에서만 설치·실행을 검증했습니다.** 2.4.x와 2.5.0보다 새 버전은 설치될 수 있지만 검증하지 않았습니다. 확장 시스템이나 문서 구조가 바뀌면 동작하지 않을 수 있으니, 문제가 생기면 사용 중인 Marinara 버전을 함께 알려 주세요.
- 문서는 설치된 Marinara에서 읽기 때문에 Marinara를 업데이트하면 결과도 달라질 수 있습니다.

## 설치 (안전장치 4단계)

확장은 프로그램 안에서 실행되는 코드라서, 마리나라는 일부러 여러 단계를
거치게 만들어 뒀습니다. 순서대로 하면 됩니다.

### ① `.env` 에 한 줄 추가

마리나라를 완전히 종료한 뒤, **설치 폴더**에서 명령창(PowerShell/터미널)을
열고 아래 한 줄을 실행하세요.

윈도우 (탐색기로 설치 폴더 열기 → 주소창에 `powershell` 입력 → 엔터):

```powershell
Add-Content .env -Value "", "ENABLE_EXTERNAL_EXTENSIONS=true"
```

macOS / Linux / Termux (설치 폴더에서):

```sh
echo "ENABLE_EXTERNAL_EXTENSIONS=true" >> .env
```

그다음 마리나라를 다시 켜세요.
> **🐳 도커로 쓰시는 경우** — `.env` 대신 `docker-compose.yml` 파일을 엽니다.
> `environment:` 줄을 찾아 그 **아래에 한 줄만** 추가하세요 (다른 줄과 앞 칸을 맞춰서):
>
> ```yaml
>       - ENABLE_EXTERNAL_EXTENSIONS=true
> ```
>
> 저장한 뒤 `docker compose up -d` 를 실행하면 적용됩니다.
> 다른 기기 브라우저로 접속해 쓰신다면 같은 자리에
> `- ADMIN_SECRET=원하는비밀값` 도 한 줄 추가하세요 (위험 구역을 열 때 필요).
> 적용됐는지 확인하려면:
>
> ```sh
> docker compose exec marinara env | grep ENABLE_EXTERNAL
> ```
>
> 값이 나오면 적용된 것이고, 안 나오면 `docker compose up -d` 를 한 번 더 실행하세요.


### ② 앱에서 확장 허용 켜기

**Settings**(설정) → **Advanced**(고급) → **Danger Zone**(위험 구역) →
**Allow third-party extension imports**(서드파티 확장 가져오기 허용)를 켭니다.

### ③ 확장 가져오기 — 둘 중 하나

#### 방법 A: GitHub 확장 관리자 (추천, 업데이트가 쉬움)

"GitHub 확장 관리자"가 이미 설치·실행 중이라면:

1. **Settings** → **Addons** → **External Extensions** 아래의
   **GitHub 확장 관리** 버튼을 누릅니다
2. 주소 칸에 `https://github.com/mallang0723/ME-docsTutor` 를 넣고
   **패키지 찾기**
3. 설치 대상에서 **`extension/manifest.json`** 을 고릅니다
   > 목록에 `v1.2.0 / marinara-docs-tutor.zip` 같은 **릴리스 항목이 함께
   > 보이거나 먼저 선택돼 있을 수 있습니다.** 릴리스 파일은 브라우저 보안
   > 정책(CORS) 때문에 다운로드가 막히니, 꼭 `extension/manifest.json` 을
   > 고르세요.
4. **내용 확인** → **설치**. 확장은 꺼진 상태로 저장되니 ④로 넘어가세요.

#### 방법 B: ZIP 파일로 가져오기

이 저장소 첫 화면의 **Code → Download ZIP** 으로 받은 zip을 쓰면 됩니다
(압축을 풀 필요 없습니다). [Releases 페이지](../../releases/latest)에 zip이
있으면 그것도 쓸 수 있지만,
릴리스는 저장소보다 늦게 갱신될 수 있습니다.

**Settings** → **Addons**(애드온) → **External Extensions**(외부 확장)에서
**Import Extension File**(확장 파일 가져오기) 버튼으로 받은 **zip 파일을
그대로** 선택합니다.

### ④ 승인하고 켜기 — 여기까지 해야 동작합니다

목록에 나타난 확장의 **전원 아이콘**(Review and run)을 누르면 승인 창이 뜹니다.

> 이 확장은 화면에 버튼을 그려야 해서 **"전체 페이지 접근"** 승인 창이
> 뜹니다. 이 권한은 확장이 마리나라 화면 전체를 읽고 바꿀 수 있다는
> 뜻입니다 — 그래서 마리나라가 일부러 무섭게 경고합니다. 코드를 신뢰할 때만
> **"Run Exact Code"**(이 코드 그대로 실행)를 누르세요.

확장 파일이 갱신되면(업데이트 등) 같은 승인 창이 다시 뜹니다. 정상입니다 —
바뀐 코드는 다시 승인해야 실행되는 안전장치입니다.

## 업데이트

- **관리자로 설치한 경우:** GitHub 확장 관리 → 이 확장의 **업데이트 확인** →
  **업데이트 보기** → **업데이트 설치** → ④처럼 다시 승인 → 페이지 새로고침.
- **예전에 ZIP으로 설치한 경우:** 지우지 말고 GitHub 확장 관리 → 이 확장의
  **GitHub 주소 연결** → 위 주소 입력 → **`extension/manifest.json`** 선택 →
  **이 저장소 연결**. 이후는 위와 같습니다. 확장 이름(`Marinara Docs Tutor
  Lorebook`)이 그대로라서 기존 설치본에 그대로 연결되고, 저장된 데이터
  (만든 로어북 기록·버튼 위치)도 유지됩니다.
- **ZIP으로 계속 쓰는 경우:** 새 zip을 같은 방법으로 가져오면 "업데이트할까요?"
  창이 뜹니다. **Save Disabled Update** 후 다시 승인하세요.

## 사용법

1. 화면에 나타난 **📚 버튼**을 누릅니다 (드래그로 위치 이동 가능, 위치는 기억됩니다)
2. 로어북을 장착할 **캐릭터를 선택**합니다
3. **"로어북 생성 + 장착"**을 누르고 완료 메시지를 기다립니다

마리나라를 업데이트한 뒤 다시 실행하면 로어북이 최신 문서 기준으로 갱신됩니다.

## 2.5.0에서 바뀐 점 (v1.3.0)

- Marinara v2.5.0에서 설치·승인·로어북 생성·재실행(항목 갱신)·캐릭터
  장착·키워드 활성화까지 실제로 확인했습니다. 버전 경고가 더 이상 뜨지 않습니다.
- v2.5.0부터 마리나라가 문서 언어(번역 팩)를 바꿀 수 있게 되어, 한국어 문서를
  켜 두면 확장이 번역본을 읽어 로어북 내용이 달라졌습니다. 이제는 문서 언어
  설정과 상관없이 **항상 영어 원문**을 읽습니다 (키워드에는 한국어 동의어가
  계속 붙습니다).
- 매니페스트를 새 형식(`marinara.personal-extension`)으로 바꾸고 버전
  (`1.3.0`)과 필요한 권한(전체 페이지 접근)을 명시했습니다. 이름은 그대로라
  기존 설치본을 업데이트할 수 있습니다.
- 코드가 바뀌었으므로 업데이트 후에는 한 번 다시 승인해야 합니다.

## 문제 해결

| 증상 | 대처 |
|---|---|
| 가져오기 메뉴가 안 보임 | ①·② 단계 확인 후 마리나라 재시작 |
| 관리자에서 "GitHub 연결이 차단되었거나…" | 릴리스 항목을 골랐을 때입니다. `extension/manifest.json` 을 고르세요 |
| 관리자에서 "같은 이름의 확장이 있습니다" | 이미 ZIP으로 설치돼 있습니다. 새로 설치하지 말고 해당 항목에서 **GitHub 주소 연결**을 쓰세요 |
| 승인했는데 📚 버튼이 안 뜸 | 페이지 새로고침. 그래도 안 되면 브라우저 콘솔(F12)의 빨간 오류를 알려주세요 |
| "docs를 읽지 못했습니다" | 마리나라 버전이 오래됐거나 문서 구조가 바뀐 경우입니다. 확장 업데이트를 확인하세요 |
| "이미 있지만 확인할 수 없어 건드리지 않습니다" | 같은 이름의 로어북을 직접 만드신 경우입니다. 그 로어북의 이름을 바꾸거나 삭제한 뒤 재실행하세요 |
| 실행 도중 확장을 꺼서 멈춤 | 이미 완료된 변경은 되돌려지지 않습니다. 다시 켜고 재실행하면 정리됩니다 |

## 알아두실 것

- 이 확장은 여러분의 마리나라 서버(같은 컴퓨터)하고만 통신합니다. 외부로
  데이터를 보내지 않습니다.
- 소스는 전부 이 저장소에 공개돼 있습니다. 승인 창의 해시는 이 코드
  그대로인지 확인하는 장치입니다.
